      1 # Assistente Acadêmico
      2 
      3 Aplicação do Assistente Acadêmico, construída em Python, Flask, Jinja, SQLite, JavaScript modular e Quarto. O código, o banco e o repositório da aplicação são independentes do sistema legado.
      4 
      5 ## Princípio de desenvolvimento
      6 
      7 A aplicação é construída em percursos verticais privados. Cada percurso precisa de documentação, teste de contrato e dados temporários antes de receber uma integração externa. O login de desenvolvimento só existe quando `ASSISTENTE_V2_ALLOW_DEV_AUTH=1` ou quando a aplicação é criada com `ALLOW_DEV_AUTH=True` nos testes; ele nunca é uma forma de autenticação de produção.
      8 
      9 ## Desenvolvimento
     10 
     11 ```sh
     12 python3 -m venv .venv
     13 . .venv/bin/activate
     14 pip install -r requirements-dev.txt
     15 flask --app wsgi:app run --debug
     16 ```
     17 
     18 A aplicação usa `instance/data/assistente_v2.sqlite3` por padrão. Para testes, use um caminho temporário definido pela fixture. O nome interno `ASSISTENTE_V2_*` permanece como contrato de configuração para não quebrar ambientes já preparados; ele não representa uma segunda aplicação pública.
     19 
     20 ## Configuração externa
     21 
     22 Copie `.env.example` apenas para um ambiente local. Os valores reais nunca entram no Git. DeepSeek, Gemini, JEV/Typesafe, Google OAuth e Quarto entram por adaptadores de serviço e configuração segura; o catálogo jurídico entra por volume externo somente leitura; o contato manual de atendimento é externo e não é integrado ao sistema; testes usam substitutos falsos. A chave Gemini é opcional e só é consultada quando uma ação estruturada do editor encontra falha técnica ou resposta inválida do DeepSeek. No VPS, ela deve ser colocada no arquivo secreto montado como `/run/secrets/gemini_api_key`, conforme `docs/ia/PROVEDORES-IA.md`; nunca no template, no JavaScript ou no banco.

     41 ## Operação publicada
     42 
     43 O domínio público `https://trab.sivaldodavi.com.br` usa o serviço `site-assistente-academico`. O banco novo fica em `/opt/servidor/data/assistente-academico/assistente_v2.sqlite3`. O código e os dados anteriores permanecem disponíveis em `/opt/servidor/sites/assistente-academico-legado/` e `/opt/servidor/data/assistente-academico-legado/`; o legado não é iniciado pelo domínio principal.
     44 
     45 O backup diário do banco é mantido pelo timer `assistente-db-backup.timer`. Ele valida a cópia e uma restauração temporária antes de mantê-la, com retenção de 14 dias. Leia `docs/ia/OPERACAO-BACKUP.md` antes de alterar banco, deploy ou recuperação.

     94 ## Princípios do produto
     95 
     96 O usuário verá o mesmo tipo de editor, etapas e documentos do site atual. A implementação é diferente: templates server-side, módulos pequenos, operações explícitas e testes por contratos de fluxo. A IA fica dentro das etapas: pode revisar campos, sugerir pergunta-problema, teses, critérios e referências, ler checklists e chamar o JEV para avaliação orientativa. Nenhuma sugestão altera o texto sem confirmação. A descrição dos fatos permanece na etapa própria do Case; não existe módulo de cronologia. Os modelos públicos completos são mantidos em `app/domain/public-models.json`, com conteúdo anonimizado portado do legado.
