     39 ## O que um push faz
     40 
     41 O hook `post-receive` do repositório principal atualiza somente a página do histórico no stagit. O push não cria imagem Docker, não muda Caddy, não reinicia serviço e não toca em banco ou secrets. A publicação é feita separadamente pelo comando de deploy, após testes e validação.
     42 
     43 O histórico principal fica em `/opt/servidor/data/stagit/assistente-academico/`. O histórico anterior fica em `/opt/servidor/data/stagit/assistente-academico-legado/`.

     60 ## Publicação
     61 
     62 O checkout `/opt/servidor/work/assistente-academico/` é uma cópia de trabalho para inspeção e staging; ele não é a fonte automática da publicação. O comando de deploy lê a referência indicada diretamente do bare repository, extrai-a para uma área temporária, substitui `/opt/servidor/sites/assistente-academico/` e reconstrói o serviço `site-assistente-academico` usando os Compose principal, override e `docker-compose.production.yml`.
     63 
     64 O diretório `/opt/servidor/sites/assistente-academico-legado/` e seu Compose de recuperação ficam fora desse fluxo. Nunca use o hook do legado para publicar a aplicação principal.
     65 
     66 O comando permanente é `/opt/servidor/deploy-site assistente-academico main`. Sua fonte versionada é `ops/deploy-site`: valida arquivos Python, templates e assets, mantém banco e secrets fora do diretório publicado e usa os três Compose de produção. Não usar o validador Hugo do aplicativo anterior.
     67 
     68 O catálogo de pesquisa fica em `/opt/servidor/data/assistente-academico/catalogs/`, montado separadamente em `/catalogs:ro`, com `RESEARCH_CATALOG_PATH=/catalogs/catalog.sqlite3`. É o acervo externo existente, não o banco de usuários. O caminho antigo do catálogo no diretório de dados `-legado` pode apontar por symlink para esse acervo, evitando duplicação e preservando a referência anterior. Nunca apontar o banco principal ou legado para o mesmo SQLite de contas.
     69 
     70 Os secrets do Assistente ficam em `/opt/servidor/secrets/assistente-academico/`. O arquivo `gemini_api_key` é opcional para o fallback e deve permanecer fora do Git. Em produção, o serviço roda como UID/GID numérico `10001:10001`, que também precisa ser o proprietário dos quatro secrets e do volume SQLite; isso é necessário porque a versão de Docker Compose do VPS ignora `uid`, `gid` e `mode` na declaração de secrets. Use modo `0400` nos secrets e modo `0750` no diretório do banco.

     90 ### Requisitos do container para Quarto (Fase 2)
     91 
     92 O Dockerfile de produção deve incluir Quarto CLI com extensões Typst e ABNT:
     93 
     94 ```dockerfile
     95 # Instalar Quarto
     96 RUN wget -qO- https://quarto.org/download/latest/quarto-linux-amd64.deb > /tmp/quarto.deb && \
     97     apt-get update && apt-get install -y /tmp/quarto.deb && \
     98     rm /tmp/quarto.deb
     99 
    100 # Instalar extensão ABNT para Typst
    101 RUN quarto add quarto-ext/typst-abnt
    102 ```
    103 
    104 Memória recomendada: 2GB+ para o container da aplicação (Quarto + Typst + IA).
    105 
    106 Depois de um deploy, confirmar `/healthz`, imports OAuth e monitor local. Alterações em units systemd precisam ser instaladas explicitamente; copiar código por si só não reinstala as units.
