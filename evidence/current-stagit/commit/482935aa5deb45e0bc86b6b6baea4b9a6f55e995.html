+# Assistente Acadêmico v2
+
+Aplicação nova do Assistente Acadêmico, construída em Python, Flask, Jinja, SQLite, JavaScript modular e Quarto.
+
+A v2 reproduzirá a experiência pública e acadêmica do site atual, mas terá banco, sessões, código e repositório independentes. O projeto legado é apenas referência funcional. Nenhum dado antigo é importado.
+
+## Estado
+
+O projeto está na Fase 1: esqueleto privado e documentação de domínio. Ainda não há login, integração real, usuário real, publicação, troca de domínio ou worker conectado ao zap-go.
+
+## Desenvolvimento
+
+```sh
+python3 -m venv .venv
+. .venv/bin/activate
+pip install -r requirements-dev.txt
+flask --app wsgi:app run --debug
+```
+
+A aplicação usa `instance/data/assistente_v2.sqlite3` por padrão. Para testes, use um caminho temporário definido pela fixture.
+
+## Configuração externa
+
+Copie `.env.example` apenas para um ambiente local. Os valores reais nunca entram no Git. DeepSeek, JEV/Typesafe, Google OAuth, Quarto e zap-go serão conectados somente em fases posteriores e sempre por configuração segura.
+
+## Princípios do produto
+
+O usuário verá o mesmo tipo de editor, etapas e documentos do site atual. A implementação será diferente: templates server-side, módulos pequenos, operações explícitas e testes por contratos de fluxo.
+
+A Linha do Tempo dos Fatos não será um formulário de redação livre. Cada fato terá data/precisão, acontecimento curto, sujeitos, categoria, fonte vinculada, status de confirmação e relevância para o conflito. Observação curta será opcional e não substituirá esses campos.

+from __future__ import annotations
+
+from dataclasses import dataclass
+from uuid import uuid4
+
+DATE_PRECISIONS = {"exact", "day_range", "month", "year", "sequence", "unknown"}
+EVENT_TYPES = {"communication", "document", "action", "deadline", "decision", "other"}
+CERTAINTIES = {"established", "alleged", "unclear"}
+RELEVANCES = {"central", "supporting", "context"}
+
+
+@dataclass(frozen=True)
+class FactEvent:
+    id: str
+    date_value: str = ""
+    date_end: str = ""
+    date_precision: str = "unknown"
+    actor: str = ""
+    event_type: str = "other"
+    fact: str = ""
+    source_ids: tuple[str, ...] = ()
+    certainty: str = "established"
+    relevance: str = "central"
+    context_note: str = ""
+
+    def as_dict(self) -> dict:
+        return {
+            "id": self.id,
+            "date_value": self.date_value,
+            "date_end": self.date_end,
+            "date_precision": self.date_precision,
+            "actor": self.actor,
+            "event_type": self.event_type,
+            "fact": self.fact,
+            "source_ids": list(self.source_ids),
+            "certainty": self.certainty,
+            "relevance": self.relevance,
+            "context_note": self.context_note,
+        }
+
+
+def new_fact() -> dict:
+    return FactEvent(id=str(uuid4())).as_dict()
+
+
+def normalize_fact(raw: object) -> dict:
+    source = raw if isinstance(raw, dict) else {}
+    source_ids = source.get("source_ids", [])
+    if not isinstance(source_ids, list):
+        source_ids = []
+    return FactEvent(
+        id=str(source.get("id") or uuid4()),
+        date_value=str(source.get("date_value") or "")[:80],
+        date_end=str(source.get("date_end") or "")[:80],
+        date_precision=source.get("date_precision") if source.get("date_precision") in DATE_PRECISIONS else "unknown",
+        actor=str(source.get("actor") or "")[:160],
+        event_type=source.get("event_type") if source.get("event_type") in EVENT_TYPES else "other",
+        fact=str(source.get("fact") or "")[:240],
+        source_ids=tuple(str(item)[:80] for item in source_ids if isinstance(item, str))[:12],
+        certainty=source.get("certainty") if source.get("certainty") in CERTAINTIES else "established",
+        relevance=source.get("relevance") if source.get("relevance") in RELEVANCES else "central",
+        context_note=str(source.get("context_note") or "")[:280],
+    ).as_dict()
+
+
+def normalize_timeline(raw: object) -> list[dict]:
+    if not isinstance(raw, list):
+        return []
+    return [normalize_fact(item) for item in raw[:80] if isinstance(item, dict)]

+import sqlite3
+from pathlib import Path
+
+from flask import current_app, g
+
+
+def get_db():
+    if "db" not in g:
+        database = Path(current_app.config["DATABASE"])
+        database.parent.mkdir(parents=True, exist_ok=True)
+        connection = sqlite3.connect(database)
+        connection.row_factory = sqlite3.Row
+        connection.execute("PRAGMA foreign_keys = ON")
+        connection.execute("PRAGMA journal_mode = WAL")
+        connection.execute("PRAGMA busy_timeout = 5000")
+        g.db = connection
+    return g.db
+
+
+def close_db(_error=None):
+    connection = g.pop("db", None)
+    if connection is not None:
+        connection.close()
+
+
+def init_db():
+    database = get_db()
+    schema = Path(current_app.root_path) / "store" / "schema.sql"
+    database.executescript(schema.read_text(encoding="utf-8"))
+    database.commit()

+# Arquitetura da v2
+
+A v2 é um monólito Python pequeno. A aplicação web renderiza HTML com Jinja; JavaScript existe para comportamento local, não para reconstruir toda a interface a partir de JSON. SQLite pertence somente à v2.
+
+## Fronteiras
+
+- `routes/`: HTTP, autenticação da requisição e composição da resposta.
+- `domain/`: regras puras e normalização, sem Flask, banco ou provedor externo.
+- `store/`: SQLite, transações e consultas.
+- `services/`: integrações externas e operações que cruzam domínios.
+- `workers/`: processos de longa duração ou tarefas assíncronas.
+- `templates/`: experiência visual e acessibilidade.
+- `static/`: CSS e módulos de interação local.
+
+Cada módulo deve ter uma responsabilidade que possa ser descrita em uma frase. Se uma rota começa a carregar regra de negócio ou HTML muito grande, a mudança deve ser feita na fronteira correta, não escondida em um helper genérico.
+
+## Estado e persistência
+
+Dados do usuário pertencem ao projeto ou à conta de forma explícita. Snapshots acadêmicos podem usar JSON validado, mas proprietário, revisão, permissões, reservas de uso e status de notificações são estruturados.
+
+Autosave usa revisão otimista. Nenhuma resposta velha pode sobrescrever uma revisão nova. A interface sempre informa salvando, salvo, conflito ou erro.
+
+## Integrações
+
+DeepSeek, JEV/Typesafe, Google OAuth, Quarto e zap-go ficam atrás de serviços com contratos pequenos. Testes substituem cada provedor por fake. Valores secretos nunca entram em código ou logs.

+# Decisões da v2
+
+## 001 — Projeto novo sem banco legado
+
+A v2 não lê nem migra o SQLite atual. O legado é uma referência funcional privada. A decisão elimina compatibilidade e permite um schema inicial coerente.
+
+## 002 — Visual preservado antes de ser redesenhado
+
+A primeira versão deve reproduzir identidade visual, textos e fluxos reconhecíveis. Limpeza de CSS só ocorre depois de validar equivalência em desktop e celular.
+
+## 003 — Linha do Tempo registra fatos estruturados
+
+A Linha do Tempo não será um bloco de descrição e relevância. Cada item representa um fato com precisão temporal, ator, tipo de acontecimento, formulação curta do fato, fontes vinculadas, certeza e relevância. Uma observação contextual curta é opcional.
+
+Isso evita usar uma narrativa longa como substituto de análise. A interpretação e a argumentação continuam nas etapas próprias do Case.
+
+## 004 — Integrações externas permanecem externas
+
+A v2 reutiliza APIs e secrets já existentes por ambiente seguro. Não há cópia de chaves para Git, frontend, imagem ou logs.
+
+## 005 — Pagamentos automáticos continuam fora
+
+Pix e atribuição de plano permanecem manuais. Nenhum gateway será implementado nesta reescrita.

+# Linha do Tempo dos Fatos
+
+## Objetivo
+
+A Linha do Tempo organiza fatos relevantes para entender um case. Ela não é um campo para escrever a descrição do caso inteiro e não substitui fatos, problema jurídico, teses ou fundamentação.
+
+## Modelo de um fato
+
+Cada registro possui:
+
+- `date_value`: data, mês, ano ou marcador de sequência;
+- `date_end`: fim opcional para intervalo;
+- `date_precision`: exata, intervalo, mês, ano, sequência ou desconhecida;
+- `actor`: pessoa, órgão ou parte envolvida;
+- `event_type`: comunicação, documento, ação, prazo, decisão ou outro;
+- `fact`: formulação curta do acontecimento, limitada a 240 caracteres;
+- `source_ids`: fontes do próprio projeto que sustentam o registro;
+- `certainty`: estabelecido, alegado ou incerto;
+- `relevance`: central, de apoio ou contexto;
+- `context_note`: observação curta e opcional, limitada a 280 caracteres.
+
+Não existe o campo legado `description`. O usuário não deve ser incentivado a escrever uma dissertação dentro da Linha do Tempo.
+
+## Experiência planejada
+
+O formulário começa perguntando “Qual fato precisa ser organizado?”, “Quando?”, “Quem aparece?”, “Que tipo de acontecimento é?” e “Qual fonte sustenta o registro?”. Campos de certeza e relevância ficam visíveis, mas não escondidos em uma redação longa.
+
+A lista mostra a ordem temporal, o fato curto, o ator, o tipo, a certeza e as fontes. A observação contextual aparece recolhida quando existe. O usuário pode corrigir a ordem, associar fontes e remover fatos.
+
+## Regras
+
+- Fato sem fonte pode existir como rascunho, mas é sinalizado antes da revisão final.
+- “Alegado” e “incerto” não são tratados como fatos estabelecidos.
+- A Linha do Tempo não cria citação nem inventa fonte.
+- A análise jurídica permanece em campos próprios.
+- A exportação decide explicitamente se os fatos entram no documento; nunca imprime observações privadas por acidente.
+- O modelo será testado com fatos exatos, aproximados, intervalos, versões conflitantes e ausência de fonte.
