+SCHEDULE_KEYS = ("report_date", "debate_date", "dissertation_date", "final_date")
+
+
+def _date(value: object) -> str:
+    text = str(value or "").strip()
+    if not text:
+        return ""
+    try:
+        return date.fromisoformat(text).isoformat()
+    except ValueError:
+        return ""
+
+
+def normalize_schedule(raw: object) -> dict:
+    source = raw if isinstance(raw, dict) else {}
+    tasks = []
+    for item in source.get("tasks", []) if isinstance(source.get("tasks"), list) else []:
+        if not isinstance(item, dict):
+            continue
+        title = str(item.get("title") or "").strip()[:180]
+        due = _date(item.get("date"))
+        if title and due:
+            tasks.append({"id": str(item.get("id") or uuid4())[:80], "title": title, "date": due})
+    return {**{key: _date(source.get(key)) for key in SCHEDULE_KEYS}, "tasks": tasks[:100]}

+# Agenda e duplicação segura
+
+## Agenda
+
+Cada snapshot de projeto pode conter quatro prazos (`report_date`, `debate_date`, `dissertation_date` e `final_date`) e até 100 tarefas com título, data e ID local. Datas são aceitas somente em ISO (`AAAA-MM-DD`) e entradas inválidas são descartadas no servidor.
+
+A agenda é organização do usuário; salvar uma data não marca entrega nem chama IA. O worker WhatsApp cria lembretes apenas para contas com opt-in, três ou um dia antes, com chave idempotente. O monitor técnico não usa essa fila.
+
+## Duplicação
+
+Duplicar cria outro registro do mesmo tipo com payload inicial vazio. Não copia título, autores, fatos, fontes, critérios, comentários, histórico, compartilhamento, revisão ou estado de IA. Isso é intencional: a ação fornece a estrutura do tipo de trabalho sem transportar dados pessoais ou administrativos.
+
+A duplicação exige sessão, CSRF e propriedade do projeto original. O banco novo não importa nem consulta projetos do legado.
