+# Git e stagit da v2 no VPS
+
+## Repositório
+
+A v2 usa o bare repository:
+
+```text
+/home/git/repos/assistente-academico-v2.git
+```
+
+O remoto de desenvolvimento é chamado `vps`:
+
+```text
+ssh://root@159.223.136.31/home/git/repos/assistente-academico-v2.git
+```
+
+A URL de navegação Git é:
+
+```text
+git://git.sivaldodavi.com/assistente-academico-v2.git
+```
+
+## O que um push faz
+
+O hook `post-receive` da v2 chama somente o gerador do stagit para atualizar a página do histórico. O push não publica a aplicação, não cria imagem Docker, não muda Caddy, não reinicia serviço e não toca em banco ou secrets.
+
+O histórico gerado fica em `/opt/servidor/data/stagit/assistente-academico-v2/`.
+
+## Fluxo normal
+
+```sh
+git status --short --branch
+python3 -m pytest -q
+git push vps main
+```
+
+Depois do push, confirme o commit remoto:
+
+```sh
+ssh root@159.223.136.31 \
+  'git --git-dir=/home/git/repos/assistente-academico-v2.git rev-parse --short refs/heads/main'
+```
+
+## Regra de publicação
+
+A v2 só será publicada no domínio quando houver decisão explícita e checklist de pré-produção. O bare repo do stagit não é o checkout de build e não deve ser usado como diretório de execução.
+
+Para publicar no futuro, será criado um checkout/staging operacional próprio da v2, com volume de dados novo e serviço separado. O deploy não reutilizará o hook do repositório legado, que possui comportamento específico de publicação do Assistente atual.
